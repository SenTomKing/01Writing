# v2.0.0 发布验收与真实模型对照

2026-10-27（北京时间）。本次完成50题、三策略的真实DeepSeek对照，并根据观察到的问题修改提示规则，补做定向回归。两个实验分别保存，不把修复前与修复后、重复题与独立题混成一个提升百分比。

## 实验设置

模型配置为deepseek-flash，关闭thinking；A直接生成、B固定流程温度0.3，C Agent温度0.2。三组获得相同授权资料，A/B直接放进提示，C按工具读取；因此比较的是完整产品策略，并非只隔离“是否使用LangGraph”这个变量。工具Schema和多轮重复上下文也计入C的token用量。

首轮代码行为对应457961f，50题均为公开自建短任务，覆盖20题基础修订和30题资料、记忆、冲突与约束。每题每策略执行一次，不是独立盲测或生产流量。任务小、证据短，不足以证明长文或大规模检索质量。资料中的实验结果、费用和Agent优势陈述都是测试输入，不是本项目实测收益。

程序检查只匹配必含词、禁用词及长度。本文案例由Codex逐条阅读候选和资料作静态复核，没有用户接受率或独立人类盲审。语义成功率与实际金额仍为未知。

## 首轮原始结果（修复前）

| 策略 | 返回候选 | 程序检查通过 | 模型请求 | 累计token | 平均耗时 | P95耗时 |
|---|---:|---:|---:|---:|---:|---:|
| A直接生成 | 50/50 | 49/50 | 50 | 10,397 | 1.86秒 | 2.03秒 |
| B固定流程 | 50/50 | 47/50 | 50 | 10,375 | 1.72秒 | 2.03秒 |
| C Agent | 47/50 | 44/50 | 164 | 271,926 | 4.63秒 | 7.65秒 |

总计264次请求、292,698 token。B本次未触发额外修复请求。P95为50次端到端耗时的最近秩分位数，包含停止的任务；网络与缓存差异使小幅耗时差异不宜过度解读。token包含供应商返回的输入、输出及可能缓存命中的计数，不直接等价于人民币费用。

这批任务没有证明Agent优于直接生成。短输入条件下工具描述占比高，多轮增加了用量和延迟；C提供了工具轨迹和引用，但仍可能过度拒答或错误理解证据。

完整原始数据：[修复前150条结果](results/v2.0.0-before-fix.json)。

## 失败归因与程序漏检

| 样本 | 观察 | 判断与处理 |
|---|---|---|
| e07，C | 输出“尚不能据此推断……导致成绩提高”，却命中禁用词 | 关键词规则不理解否定句，是程序误报；保留原分数，不事后改题美化结果 |
| e13，A/B | 写“不能确定”，未写要求匹配的“无法” | 同义表达导致程序误报 |
| e24 C、e25 B/C | 否定句含“一定比工作流好”或“保证模型只调用一次” | 同类否定语义误报 |
| e09，B | 忽略已给出的模型超时证据，仍说可能与数据库有关 | 实际内容问题，补充按资料纠错的优先规则 |
| e10/e16/e26，C | 请求澄清，未返回候选 | 存在过度询问；补充当前要求优先、允许明确表达不确定性、纠错不需保留原稿错误 |
| e06，三组 | 缩小到本校受访者，但仍沿用“喜欢产品”的调查结果 | 资料只说明调查范围，没有支持喜好结果；程序虽然通过，证据仍不足 |
| e17，三组 | 用“显著成功/显著成效”替换“革命性成功” | 仍有夸大或引入统计意味的风险，不能仅凭未出现禁用词判质量合格 |
| e23，C | 增加“只能通过重置流程设置新密码” | 给定资料没有描述重置功能，属于超出来源的产品推断 |

原始10条程序不通过中，6条属于上述同义或否定规则误报；其余包含3次停止和1次内容问题。程序通过也存在漏检，因此不报告“98%准确率”或“88%语义成功率”。

## 修正与定向回归

正式版加入共享的证据处理规则：按资料纠错时不保留错误事实；当前明确要求覆盖长期偏好；仅润色不强制要求外部事实调查；资料中的范围信息不能自动证明原稿结论；有必要时明确不确定性。Agent提示版本agent-v2.0.1，基线任务记录revision-v2.0.1。旧检查点保留原提示版本，避免恢复后冒记为新版。

补测15个不同任务，其中11个来自原集、4个为发现问题后增加的邻近场景。e10、e16各多跑一轮，共17个任务实例×三策略＝51条结果；追加84次模型请求、102,865 token。它是定向回归，不是新的盲测，不能与首轮分数直接计算泛化提升。

| 策略 | 返回候选 | 程序检查通过 | 模型请求 | 累计token | 平均耗时 |
|---|---:|---:|---:|---:|---:|
| A直接生成 | 17/17 | 17/17 | 17 | 6,426 | 1.86秒 |
| B固定流程 | 17/17 | 16/17 | 17 | 6,447 | 1.90秒 |
| C Agent | 15/17 | 15/17 | 50 | 89,992 | 4.34秒 |

e09三组均采用超时记录；e16两次Agent输出中文候选，e26按资料输出“两组无显著差异”；e23的Agent复测未再增加重置功能。新增调查范围题、功能纠错题及单纯润色题也都返回候选。B的程序不通过仍为e13“不能确定”与“无法”的词面差异。

尚未解决：e10两次Agent均把“发布范围”解释成发布受众而要求补充，说明过度澄清仍存在；e06三组仍不同程度沿用资料未支持的喜好结论；e17基线仍用“显著成功”，C改成“较为理想的结果”，仍需结合研究数据审查。新增偏好题C将“不错”改为“可行”，也显示仅满足语言要求不足以保证原意完全一致。

因此，正式版保留候选人工接受，页面明确摘录匹配不等于证据支持。可以通过明确修改要求或选择直接/固定流程处理简单任务；深入的结论—证据核验进入v3，不声称本版能自动保证事实正确。

原始数据：[修正后51条结果](results/v2.0.0-regression.json)。全轮合计348次模型请求、395,563 token，未达到450次上限。无网络搜索，没有使用私人文档。

## 复跑

服务端配置真实模型后执行；不加--live只验证演示链路。代码现在是修正后的正式版本，复跑不会重现旧提示的完全相同输出。供应商模型、缓存与随机性也可能改变结果。

```powershell
uv run python evals/run.py --live --limit 50 --max-calls 450 --output outputs/v2-full.json
uv run python evals/run.py --live --dataset evals/v2-regression-tasks.json --limit 17 --max-calls 186 --output outputs/v2-regression.json
```

每条完成后原子保存报告，completed=false表示尚未完整结束；停止或预算耗尽时按completed_trials和planned_trials核对覆盖，不能只看task_count。数据集中重复题带repeat编号。复跑会额外调用并计费。

## 工程验收与发布边界

正式代码通过149项测试及21个子测试，含账户隔离、取消、旧步骤恢复、提示词追溯和拒绝重试的依据快照。前端类型及生产构建通过。GitHub Actions验证Linux PostgreSQL、Redis/Celery、网页全流程与完整Compose。正式发布以对应提交的CI结果为准。

本机更新前备份PostgreSQL，保留已有账号、文档和历史；网页仍为localhost:8080并使用真实DeepSeek。v2范围是本地资料关键词检索、显式记忆和有界工具循环；联网、向量检索、PDF、独立语义核验、多Agent和公网部署不在本次发布中。
