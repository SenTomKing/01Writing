# v4.0.0 检索与证据判断验收

本版把新任务向量查询迁入pgvector，并在检索后装配更短的证据窗口、在提交前检查证据充分性。本报告同时保留收益、失败和复测范围；不把程序测试当真实模型准确率。

## 实验材料与控制变量

原72题检索实验及结果保持冻结。本轮另建16篇约3560字符的合成操作记录、8个主题家族、32题，按家族分开发/测试集各16题。每半含8道可回答、4道缺失、4道冲突题；冲突题要求取到两份互相矛盾的原文。标题仅使用记录编号，查询含同义表达。背景段重复较多，且每题仅1—2份授权资料，仍不是现实复杂语料的代表。

数据哈希：`eae04475c1e582bab95a707de2eb7703a8da6aa5d24e138a51a909c580930369`。比较900/120与300/60切分、BGE-M3与Qwen3-Embedding-0.6B、关键词/向量/融合，以及旧前5块截断与新窗口装配，共640条结果。正文预算统一1800字符；排序候选相同，装配不同。策略在运行前冻结，未按测试集挑冠军。

证据召回率＝被完整覆盖的标注证据条数÷所需条数；完整取证＝全部所需证据被覆盖的题数。正文长度不包含JSON与提示，不能直接等同Token费用。没有答案的问题仍可能返回相关文本，拒答必须单独检查生成行为。

## 数据库精确与近似查询

在限512MB/1核的隔离PostgreSQL容器临时表上运行1500条1024维独立高斯向量、24个固定查询。这里测的是索引的近邻召回，不是文本证据召回；CPU/容器、缓存顺序和小规模均影响耗时。精确查询作为近邻答案，HNSW确认实际使用索引。

## 真实Agent输出与失败

预先选定4题，调用同一个deepseek-flash，对比历史v3与首版v4。两组系统总预算不同（旧24k、新32k），提示和工具也改变，因此属于版本整体对照，不是单一检索变量消融。费用和逐次用量全部保存。

|任务|v3首轮|v4首轮|v4.0.1定向复测|
|---|---|---|---|
|stone-condition|context_budget|candidate|candidate|
|sail-missing|context_budget|evidence_needed|evidence_needed|
|moon-conflict|context_budget|context_budget|context_budget|
|pine-fact|context_budget|context_budget|candidate|

旧版4题都因累积读取长片段触发预算停止。首版v4完成1条候选、1条缺失询问，另外2题仍触发预算；这不是4条错误答案，但也不能算任务完成。检查轨迹发现模型重复读取已经返回的片段。v4.0.1提示合并读操作，工具JSON按实际UTF-8计算预留，累计预算改为48k，最多6次调用不变。复测2条候选、1条缺失询问、1条冲突仍预算停止。

复测候选逐条核对：stone保留86份及重复/空白排除条件；pine保留180天与法定保全例外，但回答冗长，夹带对合成材料性质的说明；sail没有编造五年成功率而询问补充，但把“没有结果数据”夸大为“只有流程记录”，说明判断仍不完美；moon已正确找出5次/8次冲突，却因没有停止而失败。原始输出均保留，不能概括成最终100%成功率。

最终v4.0.2将conflict工具判断变成直接暂停，展示差异并请用户确认；用确定性回归证明不再额外调用模型。没有再刷付费样本凑成功率；这个最终修复不混进前面的真实模型统计。模型仍可能未识别冲突，程序不能替代语义判断。

## 调用成本与复现

检索阶段Embedding 14次、50673 tokens；生成首轮27次、75503 tokens；定向复测15次、50725 tokens。生成查询Embedding累计以private/v4-eval/ledger及最后一份生成结果中的累计计数为准，不与检索阶段重复相加。没有价格/缓存账单明细，因此不捏造人民币金额。

- `python evals/v4/experiment.py`：校验并冻结方案；`--live`最多64次Embedding且限制输入字节，使用本机私有配置；`--replay`只读缓存、禁止新请求。
- `generation_eval.py`与`generation_regression.py`保留各自协议及历史输出；代码版本哈希不一致时拒绝覆盖，复现实验应检出对应实现快照或使用新实验编号。它们的语义排名使用缓存Python精确余弦，生产SQL链路由数据库回归和网页验收另证，不能冒充同一测量。
- `ann_eval.py`仅允许本机55434隔离数据库，创建临时表后回滚，不接触业务数据。
- 原始结果：[检索](results/v4-context.json)、[ANN](results/v4-ann.json)、[生成首轮](results/v4-generation.json)、[定向复测](results/v4-generation-regression.json)。

方法参考：[pgvector精确/近似查询](https://github.com/pgvector/pgvector)、[LangGraph状态与节点设计](https://docs.langchain.com/oss/python/langgraph/thinking-in-langgraph)。系统边界和实验结论来自本项目测量，不由框架文档背书。


## 本机升级与完整链路验收

213项程序测试和21项子测试通过。真实浏览器离线流程覆盖注册、登录、创建、修改、拒绝重试、刷新恢复、接受、版本恢复、下载和账户隔离；不把这些模拟流程当成模型准确率。

正式数据卷从PostgreSQL17.11升级到同17.11的pgvector镜像，固定镜像摘要。扩展实际为0.8.7；隔离ANN实验使用0.8.1，不能把不同环境混作同一次性能测量。原数据库系统排序库2.41与新镜像2.36不同，停应用重建所有业务库索引后刷新排序版本，检查权限后恢复；已有14账户、8文档、23版本、5资料数量保持。备份before-v4-20261028-101904.dump和回退镜像保存在本机私有位置。

额外独立验收账号实际导入长文，Celery完成Embedding和pgvector入库；一次真实DeepSeek任务将20人纠正为24人，保留“不包含重复签到”，带原文位置引用。数据库授权精确检索返回正文66字符，模型逐项确认两个要求后形成候选，独立核对通过；接受后重新登录读取正文一致。共4次聊天/核对请求、9884 tokens、服务记录7296毫秒，另有导入与查询Embedding，不包含在聊天Token里。这是链路冒烟测试，不能当准确率估计。验收新增自己的账号/文档/资料，没有改原有用户内容。

待后续改善：生产依赖构建仍按pyproject范围解析（CI Python环境锁定uv.lock），需进一步统一容器依赖锁；历史索引清理、真实用户语料与更多长任务评测、失败恢复和并发压力测试放在下一轮工程收尾。
