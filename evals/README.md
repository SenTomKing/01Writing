# 修订评测

20 个自建中文任务包含数字与单位、限定语、表达修订、多重约束和拒绝反馈。A 为直接生成，B 为固定流程：构建有界上下文、生成、严格结构检查、明确数字约束检查、最多一次修复。B 的数字检查仅比较标记集合，语义对应关系仍需复核；未引入资料检索或 C 组 Agent。

```powershell
python evals/run.py
python evals/run.py --live --limit 20 --max-calls 60
```

默认使用演示生成器，只验证运行与报告链路。`--live` 才调用真实模型，最多60次请求，每次最多4096输出token；按供应商实际计费，限次不是精确金额上限。全部失败与重试保留在报告中；API调用费用与评审费用分别核算。报告默认在被忽略的 outputs 中，不能公开私人原稿与密钥。

程序检查是字符串和长度的可重复断言，不足以证明事实正确。语义成功率、人工接受率、费用在未评分或未计价时保持空值。复核时隐藏方案名，随机顺序检查：是否完成必要修改，数字是否仍对应正确对象，单位、限定语和原意是否保持。仅保留数字或原样返回不能算成功。记录评审人、每项判定与分歧；本人单人评审不包装成用户群体调查。

此种子集公开供校准与回归使用，不是独立盲测集。后续按来源文档划分开发／验证／留出任务，增加到50—100个独立任务，重复运行并报告波动。同证据对照与端到端检索实验分开；比较成本和时延时固定模型、预算及初始状态。实际结果运行后再填写，不预设Agent胜出。
