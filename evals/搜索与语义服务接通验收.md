# 搜索与语义服务接通验收（2026-10-27）

本次补齐官方 DeepSeek 搜索和硅基流动 Embedding 的真实接入，沿用 v3 的资料导入、后台任务、账户隔离与人工接受流程。尚未发布新的 Git 标签。

## 实现

- DeepSeek搜索调用固定的 `/v1/tools/search`，复用现有DeepSeek密钥；保留Tavily兼容入口。auto优先已有Tavily，否则使用官方DeepSeek；none关闭搜索。每个修订任务仍须用户勾选联网。
- 查询1至128字符，最多5条结果；只返回链接和摘要，引用仍需另行受限抓取正文。不自动采用搜索返回的正文，不新增DeepSeek Fetch适配。
- 硅基流动地址 `https://api.siliconflow.cn/v1`、模型 `BAAI/bge-m3`。真实返回1024维浮点向量。
- 新索引最多900字符，同页相邻片段最多重叠120字符，优先段落与句末，不跨PDF页边界重叠。保留原文字符起点、页码、内容哈希、模型地址指纹、维度和切分版本。
- 向量服务错误或维度不匹配时，查询明确退回关键词；重建失败不保存半成品。正文改变时不使用旧索引。模型改变后须重建已有资料。

## 使用与边界

刷新本地网页，在资料区为旧资料点击“重建索引”，等待完成；新导入会自动建立向量。新建修订时勾选资料。已有任务保留创建时的资料快照，不会因重建静默替换其依据。

向量存放于现有Docker PostgreSQL的JSON字段，查询对本任务已授权快照做精确余弦计算，结合关键词排名以RRF融合，返回前5条。没有pgvector、HNSW或全库向量召回，不应表述为大规模向量数据库已完成。

切分参数是当前可运行默认值，不代表已证明最优。后续若评价召回率，应人工标注相关原文证据位置，用同一查询集合对比切分和检索策略；记录Recall@K、证据覆盖、延迟与调用成本，不能用本次单条命中冒充效果提升。

密钥仅在被Git忽略的.env.deploy及容器环境中，未进入前端或公开仓库；原有用户资料没有自动批量送去向量化。
